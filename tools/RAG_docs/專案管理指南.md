# 資訊管理系 專案管理指南

## 專案生命週期

### 1. 專案啟動階段
- **需求分析**：與業務單位進行需求訪談
- **可行性評估**：技術、時程、預算評估
- **專案核准**：提交專案提案書，經系務會議核准

### 2. 規劃階段
- **工作分解結構 (WBS)**
- **時程規劃**：使用 Gantt Chart
- **風險評估**：識別並制定風險應對策略
- **資源分配**：人力、設備、預算分配

### 3. 執行階段
- **每週進度會議**：星期三下午 2:00
- **版本控制**：每週至少一次程式碼提交
- **測試階段**：單元測試、整合測試、使用者測試

### 4. 結案階段
- **系統上線**：正式環境部署
- **文件交付**：使用者手冊、維護文件
- **教育訓練**：使用者培訓
- **專案檢討**：lessons learned 文件

## 專案團隊角色

### 專案經理 (PM)
- 負責專案整體規劃與執行
- 協調團隊成員與資源
- 監控專案進度與品質

### 系統分析師 (SA)
- 需求分析與系統設計
- 使用者介面設計
- 系統架構規劃

### 程式設計師 (Developer)
- 程式碼開發與實作
- 單元測試撰寫
- 技術文件撰寫

### 測試工程師 (Tester)
- 測試計畫制定
- 測試案例執行
- 缺陷回報與追蹤

## 品質管理

### 程式碼品質
- 程式碼覆蓋率需達 80% 以上
- 複雜度 (Cyclomatic Complexity) 不超過 10
- 每次提交需通過靜態分析檢查

### 文件品質
- 使用者故事 (User Story) 格式撰寫需求
- API 文件需包含範例程式碼
- 系統架構圖需使用 UML 標準

### 測試品質
- 缺陷密度不超過 2 defects/KLOC
- 測試案例覆蓋率達 90% 以上
- 效能測試需符合 SLA 要求

## 溝通管理

### 定期會議
- **每日站立會議**：每天上午 9:00，15分鐘
- **每週進度會議**：星期三下午 2:00，1小時
- **每月專案檢討會議**：每月最後一個星期五，2小時

### 溝通工具
- **即時通訊**：Microsoft Teams
- **專案管理**：Azure DevOps
- **文件協作**：SharePoint
- **程式碼管理**：GitHub Enterprise

### 報告制度
- **每週進度報告**：星期四前提交
- **月報**：每月 5 日前提交
- **專案里程碑報告**：達成里程碑後 3 日內提交

## 風險管理

### 常見風險類型
1. **技術風險**：新技術導入困難
2. **資源風險**：人力不足或技能不符
3. **時程風險**：需求變更導致延遲
4. **品質風險**：測試不充分

### 風險應對策略
- **規避**：選擇成熟穩定的技術
- **轉移**：外包非核心功能
- **減輕**：增加測試時間與人力
- **接受**：制定應變計畫
